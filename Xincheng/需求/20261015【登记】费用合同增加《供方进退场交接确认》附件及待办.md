# 【登记】费用合同增加《供方进退场交接确认》附件及待办

## 一、变更概述

### 需求信息

### 描述

1. 费用合同签署后发送待办，项目工程物业负责人。样式同舞狮确认待办，项目工程负责人提交后，区域工程负责人复核。项目工程物业负责人岗位编号：SG_CS_002，区域工程物业负责人岗位编号：SG_QY_001。任何一个人处理其他人待办也同步处理。发送及填报日志表参考舞狮待办。
2. 费用合同增加附件类型：供方进退场交接确认函。待办确认后附件上传到对应费用合同中。
3. 对应合同的科目：保洁、石材 H2020301、消防维保、电梯维保 H2020101。
4. 待办页面标题：供方进退场交接确认函。项目确认状态：已交接/不需交接；区域确认状态：已交接/不需交接。参考信息：项目、合同编号、合同名称、供应商、合同金额、经办人。附件：供方进退场交接确认函，已交接时必填。
5. 待办消息文本：XX项目XX合同已经盖章，请确认供方进退场交接状态。
6. 项目只有确认操作，区域可确认后打回。确认后事项完成，附件写入合同附件；打回后重新发送项目待办，区域待办完成。

### 变更背景

保洁、石材、消防维保、电梯维保类费用合同签署（双方盖章）后，供方进退场交接目前依靠线下确认，系统内没有交接确认记录，确认函也不归档，后续追溯困难。本次将交接确认搬到线上：盖章状态经接口回写为双方盖章后，按项目、区域两级推送待办，项目工程物业负责人确认、区域工程物业负责人复核，确认函回传至费用合同附件，形成线上闭环。

待办框架参照舞狮奖金待办实现：EKP 待办工具、待办类型配置、岗位配置、待办实现类、发送日志与确认记录表全部沿用同一套机制，避免另起一套待办体系。

**边界条件**

| 测试点 | 测试内容 | 预期结果 |
|--------|----------|----------|
| 触发时机 | 盖章状态接口回写、ZSTMM0009-ZSFQZ 更新为 '30'（双方盖章）且科目命中 | 自动创建项目待办；未回写双方盖章、未命中科目不发 |
| 科目命中 | 合同详情行 ZSTMM0011-ZYSKM：保洁、消防维保按科目名称一对一匹配；石材按 H2020301、电梯维保按 H2020101 按代码匹配 | 任一明细行命中即创建待办 |
| 幂等 | 同一合同重复回写盖章状态、重复触发 | 已有未关闭的同类型待办时不重复创建 |
| 岗位无人 | 岗位未配置或按项目/区域找不到负责人 | 不发待办，写日志并给出提示，不阻塞合同流程 |
| 多负责人 | 同岗位配置多人 | 每人均收到待办；任一人处理后关闭该合同该类型全部待办 |
| 项目确认=已交接 | 附件校验 | 至少 1 个附件，否则拦截并提示 |
| 项目确认=不需交接 | 附件与必填 | 不强制附件 |
| 区域确认=已交接 | 事项完成 | 附件写入合同附件，关闭区域待办，事项完成 |
| 区域确认=不需交接 | 事项完成 | 关闭区域待办、事项完成，不写合同附件 |
| 区域打回 | 打回处理 | 关闭区域待办、清空项目确认状态、保留已上传附件、重新发送项目待办 |
| 重复确认 | 已确认后再次提交 | 拦截并提示，不允许重复确认 |
| 合同无项目/项目失效 | 取人失败 | 跳过并记日志，不阻塞合同流程 |
| 并发 | 项目、区域同时操作同一合同 | 按合同 objbkey 加锁，避免状态互相覆盖 |

**易错点 / 注意事项**

| 序号 | 易错点 | 说明 |
|------|--------|------|
| 1 | 触发点不幂等 | 盖章状态回写可能重复触发，必须按合同+待办类型判重，避免重复待办 |
| 2 | 区域岗取人维度 | 现有 ZSCL_RE_EKPINFO=>GET_POST_EMPLOYEE_BATCH 按 zprojid 过滤；区域岗 SG_QY_001 需先由合同所属项目定位区域，再按区域取人 |
| 3 | 任一人处理同步关闭 | 关闭待办须按 docno+type 关闭全部接收人任务，仅关闭当前用户会留下孤儿待办 |
| 4 | 附件落库口径 | objecttype='YBHT'、documentnumber=合同 objbkey；token 落库后合同附件区需立即可见 |
| 5 | 打回重发 | 打回后先关区域待办再发项目待办，并清空项目确认状态，避免重复待办或状态残留 |
| 6 | 科目判断字段 | 使用 ZSTMM0011-ZYSKM（代码）及科目名称匹配，不使用可编辑文本 ZYSKMTXT，避免名称变更失效 |
| 7 | 待办页越权 | 仅当前节点岗位负责人可确认；非本人岗位、非当前节点需拦截 |
